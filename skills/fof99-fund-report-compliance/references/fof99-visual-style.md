# 火富牛合规预审视觉规范

用于基金及 FOF 报告合规预审成果。目标是形成“克制、可信、可定位、可执行”的审阅体验。品牌视觉服务于风险识别和复审效率，不得让成果看起来像营销材料或正式合规批准。

## 1. 使用原则

- 风险问题表和原文定位是主体，图表只是摘要工具。
- 白底、深色正文、少量品牌红橙点缀；大面积红色只用于确需暂停发布的高风险提示。
- 同时使用风险文字、编号和颜色，不得只靠色彩判断等级。
- 原文、判断、证据要求和推荐改写必须视觉分离，避免把改写文本误认为原文。
- 纯 Markdown 使用标题、引用块、风险表和复选框建立层级，不使用 HTML 模拟卡片。
- HTML、PDF、DOCX 或网页成果可使用卡片、状态条和固定表头，但必须保证打印与黑白阅读仍可辨识。
- 只有实际使用火富牛 MCP 数据时，才将对应核验来源标为“火富牛 MCP”。

## 2. 品牌色与风险语义

| 令牌 | 色值 | 合规预审用途 |
|---|---|---|
| 品牌主色 | `#E8663C` | 报告标题、链接、品牌点缀、重点数字 |
| 高风险 | `#D1442A` | 建议暂停发布、重大误导风险、必须处理 |
| 高风险浅底 | `#FFF0EB` | 高风险卡片背景，不用于整页铺色 |
| 中风险 | `#F5A623` | 修改后复审、重要信息缺口 |
| 提示信息 | `#4A90D9` | 表达优化、口径说明、参考链接 |
| 未见明显异常 | `#2E8B57` | 仅表示当前范围内未见明显问题 |
| 待核验 | `#8E8E93` | 缺数据、缺适用背景、来源冲突 |
| 主文字 | `#1A1A1A` | 标题、原文、判断正文 |
| 次文字 | `#666666` | 说明、脚注、复审边界 |
| 边框 | `#EBEDF0` | 表格线、卡片边框、分隔线 |
| 模块底色 | `#FAFBFC` | 原文摘录、材料清单、次级区块 |

固定风险标签：

- `🔴 高风险`：发布前必须处理并由有权限人员复核。
- `🟠 中风险`：补充依据或修改后复审。
- `🔵 提示项`：改善表达、标注、口径或一致性。
- `⚪ 待核验`：证据不足，不能推定为安全或违规。

绿色只用于“在本次范围内未见明显异常”，不得写成“合规通过”。涉及报告内收益数据时，可按中国市场习惯使用红涨绿跌，但必须与合规风险色置于不同图表并清楚标注语义。

## 3. 信息结构

正式成果按以下顺序组织：

1. **报告头部**：报告名称、版本、用途、适用地区、受众、数据截止日和运行模式。
2. **预审结论条**：四档结论、最重要风险和预审边界。
3. **风险计数**：高风险、中风险、提示项、待核验四个摘要项。
4. **优先处理事项**：最多三项，注明动作、所需证据和责任建议。
5. **风险明细表**：按等级、传播影响和可执行性排序。
6. **重点问题卡片**：仅用于高风险或复杂问题，分开呈现原文、风险说明、证据和推荐改写。
7. **数据核验与发布条件**：列出差异、缺口、复审条件和人工确认项。
8. **来源与声明**：适用依据、检索日期、数据来源和预审边界。

HTML 或文档卡片建议：圆角 `8px`，边框 `1px solid #EBEDF0`，阴影 `0 1px 4px rgba(0,0,0,0.04)`，内边距 `18–20px`，模块间距 `20–24px`。合规成果使用更轻的阴影和更少的渐变，保持审阅底稿感。

## 4. 重点问题卡片

每张问题卡片按固定次序显示：

1. `R-编号｜风险等级｜问题标题`
2. **位置**：页码、章节、段落或图表。
3. **原文**：使用浅灰底引用块，保留必要上下文。
4. **风险说明**：使用对应等级的左侧色条，同时保留文字等级。
5. **证据或核验要求**：使用信息蓝标签，不与判断结论混排。
6. **处理建议**：使用动词开头，明确删除、补充、限制传播或人工复核。
7. **推荐改写**：使用白底或浅蓝底，明确标为建议文本；未核验数据保留占位符。

不得用删除线、鲜艳高亮或大量批注效果替代清晰的“原文—问题—动作”结构。

## 5. 图表使用边界

默认不制作图表。仅在问题数量较多、用户需要管理层摘要或数据差异明显时使用：

| 场景 | 可选图表 | 限制 |
|---|---|---|
| 风险等级分布 | 横向条形图 | 必须同时显示数量；不建议只用环形图 |
| 风险类别分布 | 排序条形图 | 类别不超过八项，颜色以品牌主色深浅区分 |
| 数据核验差异 | 哑铃图／差异条 | 标明原值、核验值、口径与截止日 |
| 页码或章节聚集 | 简单热区表／条形图 | 用于定位，不把问题数量直接等同风险严重度 |

不要为了“更好看”生成词云、3D 图、仪表盘指针或无法支持审阅动作的装饰图。图表后必须跟一句管理含义和对应问题编号。

## 7. 表格、字体与可访问性

- 风险明细表优先于图表；表头固定、列名简短、原文摘录控制长度。
- 编号、等级、位置和处理建议不得在窄屏或打印版中被隐藏。
- 百分比通常保留两位小数；报告原值与核验值保留各自原始精度并说明差异。
- 缺失显示“待核验”，不使用空白或 `0`；尚未检查显示“未检查”，不写“无风险”。
- 字体优先级：`PingFang SC`, `Microsoft YaHei`, `Helvetica Neue`, `-apple-system`, `sans-serif`。
- 黑白打印时仍应依靠等级文字、编号、图案或边框辨识；不要让红绿颜色成为唯一线索。
