# 火富牛 MCP 路由｜私募基金管理人尽调

仅在当前环境存在已授权的火富牛 MCP 工具时读取。优先匹配 `mcp__fof99_mcp_mall_stream__*`，也兼容其他火富牛命名空间；始终以实时工具描述和参数为准。

## 只读、安全与缓存

- 只调用查询、比较和只读计算工具；禁止上传净值、创建或修改产品、调仓和交易。
- 使用 `工具后缀 + 标准化参数 + 日期区间` 作为任务内缓存键；完全相同的查询只调用一次。
- 空结果、无权限、字段缺失和工具错误分别记录，不把任何一种解释为零或无风险。
- 工具返回私有数据时，只保留报告所需最小字段，不扩大查询对象或传播范围。
- 正式报告写数据来源和覆盖边界；工具名、失败日志和调用次数只进入内部底稿。

## 检索档位

| 档位 | 使用场景 | 典型调用量 | 产品业绩深度 |
|---|---|---:|---|
| 快速初筛 | 早期筛选或短时任务 | 8–12 | 产品元数据，默认不拉净值 |
| 标准尽调 | 默认 | 12–18 | 产品全景、管理人策略指数、最多 3 只代表产品 |
| 业绩深挖 | 准入或业绩决定结论 | 18–30 | 最多 5 只可用净值产品，选择性增加指标与比较 |
| 全产品业绩审计 | 用户明确要求 | 先估算 | 单独任务，不在默认管理人尽调中自动展开 |

默认使用“标准尽调”。调用量是计划护栏而非必须用满的额度；把计划和实际调用写入内部底稿，不写入正式报告。先完成身份、团队、策略和重大风险底座，只有数据会改变结论时才增加产品级查询。

## 第一阶段：身份与管理人底座

| 目的 | 工具后缀 | 使用说明 |
|---|---|---|
| 解析登记编号 | `get_company_code` | 只有名称时先调用；出现多候选时不要猜测 |
| 管理人基本信息 | `company_info` | 使用精确登记编号 |
| 规模与产品数 | `company_scale` | 分开记录协会规模区间、披露规模和数据日期 |
| 股东 | `company_shareholder` | 重大事项仍需当前企业登记或正式材料核验 |
| 高管 | `company_senior` | 区分职务和从业资格状态 |
| 法定代表人履历 | `company_senior_list` | 履历文本仍需一致性核验 |
| 核心投资人员 | `company_manager` | 关注策略职责、年限、工作量与关键人集中 |
| 代表产品／策略概况 | `company_detail` | 用于管理人概览，不替代完整产品目录 |

`get_company_strategy` 返回平台策略分类树，不是某一家管理人的策略清单。仅在需要解析策略 ID 或标准化分类时使用，不得据此判断目标管理人实际开展的策略。目标管理人的策略应结合 `company_detail`、`company_fund_list`、材料和策略指数列表判断。

## 第二阶段：诚信、风险与舆情

| 目的 | 工具后缀 | 使用说明 |
|---|---|---|
| 协会诚信信息 | `company_risk_sincerity` | 记录项目日期、状态、分页和查询日期 |
| 协会机构提示 | `company_risk_tip` | 空结果不等于不存在风险 |
| 监管措施 | `company_opinion_list` | `type="1"`，与一般新闻分开查询 |
| 舆情信息 | `company_opinion_list` | `type="2"`；舆情是线索，不是已核实事实 |

对处罚、监管措施、纪律处分和重大司法事项，必须继续核验当前官方原文。舆情分页按时间倒序检查；超过 1,000 条时先征得用户同意。

## 第三阶段：产品全景

使用 `company_fund_list`：

1. 先以 `fund_state=0` 查询第一页，记录 `page`、`pagesize`、总量和返回量；
2. 总量未覆盖时继续分页，直至完成、达到用户范围或触发 1,000 条确认阈值；
3. 需要区分受托／顾问时再按 `manage_type` 补充分组，不重复拉取相同范围；
4. 复用产品目录返回的基金代码，不再逐只调用 `get_fund_code`；
5. 先生成产品状态、策略、成立年份、净值可见性和新鲜度统计，再选择代表产品。

未完成全部分页时只能称为“已返回范围”，不得写成“全部产品”。

## 第四阶段：代表产品与业绩

| 目的 | 工具后缀 | 使用说明 |
|---|---|---|
| 产品基本信息 | `fund_info` | 仅补充代表产品缺失的决策相关字段 |
| 平台净值 | `fund_platform_price` | 默认净值预检；记录起止日、频率和最后净值日 |
| 团队净值 | `fund_company_price` | 与平台净值分开保存，不静默拼接 |
| 单基金指标 | `get_fund_factor` | 仅在净值预检成功后使用 |
| 净值及基准比较 | `compare_view` | 对齐区间、频率、净值类型和基准 |
| 年度表现 | `compare_annual` | 样本不足或跨年不完整时说明 |
| 其他指标 | `compare_factors` | 只取会改变判断的指标 |
| 正负收益统计 | `compare_positive` | 明确周频或月频 |
| 相关性 | `compare_corr`／`compare_corr_matrix` | 短样本不得下稳定性结论 |
| 估值新鲜度 | `fund_valuation_info` | 用于停更、估值表解析和数据时效判断 |
| 同策略分布 | `get_market_category` | 策略、区间和指标口径必须匹配 |

`get_fund_factor` 中容易混淆的参数：`nav_source` 表示复权／累计／单位净值类型，`nav_type` 表示平台／团队净值来源。调用前读取实时参数说明，不能按英文字段名直觉填写。

## 管理人策略指数

1. 用 `get_company_strategy_index` 获取目标管理人的策略指数及 ID；
2. 用 `company_strategy_index_price` 查询指定指数的净值序列；
3. 把策略指数明确标为管理人层面参考，不等同于可投资产品净值；
4. 指数停更、样本选择或编制口径不明时降低证据置信度。

## 停止条件

- 代表产品无代码、净值不展示、返回空序列或权限不足：停止该产品后续指标与比较查询。
- 可用净值覆盖率低于 10%：不逐只追查，转为透明度缺口并建立深挖队列。
- 默认尽调最多 3 只代表产品；业绩深挖最多 5 只。
- 只有用户明确要求全产品业绩审计，才估算产品数、调用量和时间后扩展。
- 单个分支失败时保留其他已完成模块，不从头重跑整个查询链。

## 代表产品选择

默认依次考虑：核心策略中历史较长的运作产品、能够检验风险或矛盾的产品，以及确有新增信息的近期产品。去除重复份额、实质相同的联接／顾问条目。记录选择理由并披露选择偏差，不把代表性证据称为全量业绩。
