# 火富牛诊断视觉规范

用于基金深度诊断的正式报告、图表和可视化成果。目标是形成“专业研究、证据清晰、重点鲜明”的火富牛视觉体验，而不是用装饰替代分析。

## 1. 使用原则

- 先传达研究结论，再展示指标与证据，最后说明适用条件和限制。
- 白底为主，品牌红橙只用于主基金、关键数字和标题点缀；避免整页大面积高饱和红色。
- 纯 Markdown 不使用 HTML 模拟卡片；通过标题、引用块、短表格和留白建立层级。
- HTML、PDF、DOCX 或网页成果可使用真实卡片、圆角、阴影和响应式布局。
- 没有图表工具时，保留相同内容顺序，以 Markdown 表格和文字结论降级。
- 只有实际使用火富牛 MCP 数据时，才将数据来源标为“火富牛 MCP”。

## 2. 品牌色与语义色

| 令牌 | 色值 | 诊断场景用途 |
|---|---|---|
| 品牌主色 | `#E8663C` | 主基金曲线、关键结论、核心 KPI、链接 |
| 品牌深色 | `#D1442A` | 标题点缀、重要风险、悬停状态 |
| 品牌浅底 | `#FFF0EB` | 结论摘要、重点发现卡片底色 |
| 信息蓝 | `#4A90D9` | 第二基金、辅助指标、解释信息 |
| 暖金 | `#F5A623` | 观察事项、证据不充分、临界状态 |
| 下跌绿 | `#27AE60` | 仅用于收益率或净值的下跌语义 |
| 中性灰 | `#8E8E93` | 基准、待核验、次要信息 |
| 主文字 | `#1A1A1A` | 标题、正文、主要数据 |
| 次文字 | `#666666` | 指标解释、图例、辅助信息 |
| 边框 | `#EBEDF0` | 卡片边框、表格线、分隔线 |
| 模块底色 | `#FAFBFC` | 卡片和证据区背景 |

严格区分两套语义：

- **业绩图表**：正收益／上涨使用 `#E8663C`，负收益／下跌使用 `#27AE60`，基准使用 `#8E8E93`。
- **研究状态**：重要风险使用 `#D1442A`，持续观察使用 `#F5A623`，信息说明使用 `#4A90D9`，待核验使用 `#8E8E93`。

不要仅按数字正负着色。最大回撤、波动率、费用率等指标必须按指标含义和比较基准表达，不套用“正红负绿”。颜色之外同时使用 `+/-`、标签、线型或“风险／观察／待核验”等文字。

## 3. 信息结构

正式成果按以下顺序组织：

1. **报告头部**：基金名称、报告类型、数据区间、截止日和运行模式。
2. **研究结论条**：研究分级、置信度和一句话核心判断。
3. **KPI 区**：优先展示区间收益、最大回撤、修复时长、年化波动和风险调整收益；最多 4–6 项。
4. **核心图表**：先净值与基准，再回撤；其他图表按问题需要出现。
5. **证据表与分析**：每张图或每组指标后紧跟一至两句解释。
6. **适用条件**：组合角色、必要持有条件、不适用情形和反证。
7. **来源与边界**：数据来源、截止日、口径、未核验项和免责声明。

HTML 或文档卡片建议：圆角 `8px`，边框 `1px solid #EBEDF0`，阴影 `0 1px 4px rgba(0,0,0,0.06)`，内边距 `20px`，模块间距 `24px`。KPI 数字建议 `26–28px`，正文建议 `14px`。

## 4. 图表选择

| 诊断问题 | 优先图表 | 视觉要求 |
|---|---|---|
| 净值与相对表现 | 折线图 | 主基金品牌红橙实线；基准灰色虚线；不同份额不得仅靠颜色区分 |
| 回撤与修复 | 水下／面积图 | 回撤线用深红，浅红填充；标注峰值、谷值和修复日 |
| 滚动收益或胜率 | 折线图／柱状图 | 正红负绿，零轴清楚，标明窗口长度 |
| 风格或因子暴露 | 分组条形图／点图 | 优先于雷达图；必须统一量纲或标准化口径 |
| 关键阶段对比 | 分组柱状图 | 阶段名称和日期直接标注，避免只写“牛市／熊市” |
| FOF 底层配置 | 横向条形图／矩形树图 | 突出前五大暴露和未穿透比例；小项合并为“其他” |

图表标题必须包含对象与指标，副标题包含数据区间。图下注明数据来源、截止日和一句核心解读。图表无法支持结论时宁可不画。

## 6. 表格与数字

- 百分比通常保留两位小数，净值通常保留四位；不同来源精度不足时保留原精度。
- 数值右对齐，文字左对齐；日期使用统一格式。
- 最优、最大或最差项必须写明比较口径，不仅靠颜色突出。
- 缺失值显示“不可得”，冲突值显示“存在来源差异”，不得用 `0` 代替。
- 表格超过 12 行时优先排序、分组或展示重点，并提供完整明细作为附表。

## 7. 字体与可访问性

字体优先级：`PingFang SC`, `Microsoft YaHei`, `Helvetica Neue`, `-apple-system`, `sans-serif`。表格数字可使用支持表格数字的等宽字体。正文与背景保持足够对比度；红绿组合必须辅以正负号、箭头、标签或线型。不得使用过多 emoji，正式报告只保留必要状态符号。
