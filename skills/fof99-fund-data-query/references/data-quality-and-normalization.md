# 数据质量与标准化

## 状态词表

每个请求字段使用以下一种状态：

| 状态 | 含义 |
|---|---|
| 已返回 | 来源返回有效值且口径可识别 |
| 部分返回 | 仅覆盖部分对象、区间或字段 |
| 不可得 | 当前来源不提供或数据尚未披露 |
| 未命中 | 查询对象或记录没有匹配结果 |
| 无权限 | 数据存在但当前授权不可访问 |
| 来源冲突 | 不同来源的值、日期或口径不一致 |
| 待确认 | 对象、份额、币种或口径无法唯一确定 |

不得用空字符串、`0`、`-` 混合表达缺失。结构化交付可使用 `null`，同时提供 `status` 和 `status_reason`。

## 字段标准化

- 日期统一为 `YYYY-MM-DD`；保留原时区和查询时间。
- 基金代码保留前导零；代码与份额类别分开存储。
- 比例结构化为小数或百分数时声明单位，不混用 `0.05` 与 `5%`。
- 金额保留币种和单位；万元、亿元不得只留数值。
- 净值明确单位、累计或复权类型；来源不同的净值不静默拼接。
- 基金类型至少区分公募、私募、自建、私募 FOF 和组合。
- 管理人名称保留来源原文，并可另设标准化名称字段。
- 基准同时记录名称、代码、正式／分析用途和选择理由。

## 时间序列检查

1. 按日期排序并检查重复记录。
2. 检查缺失期、停更、频率变化和非预期空档。
3. 检查异常跳变，并优先核对分红、拆分、份额变化、申赎和估值调整。
4. 多序列比较时计算共同区间、各自样本数和缺失比例。
5. 不用前值填充掩盖停更；如为展示而填充，必须保留填充标志。

## 覆盖率与新鲜度

- 字段覆盖率：`有效返回字段数 / 请求字段数`。
- 对象覆盖率：`成功返回对象数 / 请求对象数`。
- 时间覆盖率：实际有效区间相对请求区间的覆盖程度，并注明交易日或自然日口径。
- 数据新鲜度：查询日期减去实际数据日期；不同数据类型分别评价，不设置跨类型统一阈值。

## 来源冲突

冲突表至少包含字段、来源 A、来源 B、各自数据日期、口径差异、可能原因和建议确认动作。不要自动选择数值更大、更新或更有利的版本；官方披露与平台结构化值的适用用途可能不同。

## 派生计算

派生字段必须记录：公式、输入字段、输入来源、计算区间、频率、缺失处理和计算时间。无法复现的计算不得标为“已核验”。
