# 火富牛 FOF 组合风险扫描视觉规范

用于组合风险扫描报告、风险仪表盘和相关图表。目标是形成“风险优先、层级清楚、可快速处置”的火富牛视觉体验，使读者先看到风险状态和数据盲区，再查看指标与证据。

## 1. 使用原则

- 第一屏或第一页必须展示总体灯号、数据层级、关键覆盖率和前三项优先事项。
- 品牌红橙用于标题和关键强调；红黄绿灰灯号用于风险语义，两者在风险仪表盘中保持一致。
- 灰灯必须与绿灯同等可见，避免把数据缺失包装成低风险。
- 图表必须服务于风险传导、集中度、相关性、流动性或压力情景，不制作装饰性仪表盘。
- 纯 Markdown 使用灯号文字、摘要表和风险清单建立层级；HTML、PDF、DOCX 或网页成果可使用真实卡片与网格布局。
- 无图表工具时使用排序表、文本热区和简要结论降级，不影响扫描结论。
- 只有实际使用火富牛 MCP 数据时，才将对应数据来源标为“火富牛 MCP”。

## 2. 品牌色与风险灯号

| 令牌 | 色值 | 风险扫描用途 |
|---|---|---|
| 品牌主色 | `#E8663C` | 报告标题、品牌点缀、关键数字 |
| 红灯 | `#D1442A` | 已突破边界、重大风险、P0/P1 事项 |
| 红灯浅底 | `#FFF0EB` | 高风险摘要卡片背景 |
| 黄灯 | `#F5A623` | 接近边界、趋势恶化、限期核验 |
| 绿灯 | `#2E8B57` | 当前证据和约束下未见显著异常 |
| 灰灯 | `#8E8E93` | 缺失、过期、冲突或方法不适用 |
| 信息蓝 | `#4A90D9` | 基准、补充信息、次级系列 |
| 紫罗兰 | `#7B68EE` | 第三系列、策略维度 |
| 青绿 | `#2EB5A6` | 第四系列、流动性缓冲 |
| 主文字 | `#1A1A1A` | 标题、正文、主要数据 |
| 边框 | `#EBEDF0` | 卡片和表格分隔 |
| 模块底色 | `#FAFBFC` | 次级模块、数据说明 |

风险灯号固定为：`🔴 红灯`、`🟡 黄灯`、`🟢 绿灯`、`⚪ 灰灯`。不得用品牌红代表“上涨”来绘制风险主视图。只有独立的收益或净值子图可以采用中国市场红涨绿跌惯例，并必须在标题或图例中明确“收益语义”。

颜色之外必须显示灯号文字、优先级、指标值和阈值。最大回撤等负值指标不得根据正负号机械着色。

## 3. 仪表盘信息结构

正式成果按以下顺序组织：

1. **报告头部**：组合名称、估值日、分析区间、数据层级、运行模式。
2. **总体状态条**：总体灯号、一句话结论、结论置信度。
3. **摘要卡片**：红灯数、黄灯数、灰灯数、关键数据覆盖率，最多 4–6 项。
4. **优先事项**：按 P0／P1／P2 排序，显示影响、动作和期限。
5. **风险矩阵与核心图表**：集中度、风险贡献、相关性、流动性和压力情景。
6. **完整风险清单**：每项包含阈值、证据强度和下一步。
7. **补数与监测计划**：灰灯数据、复核日期和触发动作。
8. **来源与边界**：数据来源、截止日、覆盖率、模型限制和免责声明。

HTML 或文档卡片建议：圆角 `8px`，边框 `1px solid #EBEDF0`，阴影 `0 1px 4px rgba(0,0,0,0.06)`，内边距 `20px`，模块间距 `24px`。风险卡片只用浅色背景和左侧状态条，避免大面积高饱和填色。

## 4. 图表选择

| 风险问题 | 优先图表 | 视觉要求 |
|---|---|---|
| 单产品／管理人／策略集中 | 排序横向条形图 | 标出阈值线、前五项和未分类比例 |
| 权重与风险贡献错位 | 分组条形图／哑铃图 | 权重用信息蓝，风险贡献用品牌红橙；直接标注差值 |
| 相关性与风险簇 | 热力图 | 低相关浅蓝、高相关深红；显示数值，缺失格使用灰色斜纹或 `N/A` |
| 回撤与修复 | 水下／面积图 | 深红边线、浅红填充；标注峰谷和未修复区间 |
| 流动性期限 | 累计阶梯图／横向堆叠条 | 可变现资产与资金需求并列；未知部分固定使用灰色 |
| 压力测试 | 瀑布图／排序条形图 | 损失来源按贡献排序，区分事实、模型估计和假设 |
| 综合风险状态 | 风险矩阵 | 纵轴影响、横轴紧迫性；气泡大小表示暴露，标签显示证据强度 |
| FOF 穿透 | 矩形树图／桑基图 | 仅在路径清晰时使用；突出重复暴露和未穿透比例 |

饼图仅用于类别少于六项且总和明确为 100% 的静态构成。禁止 3D 图、速度表式仪表盘和会夸大微小差异的截断坐标轴。

## 6. 数据、表格与可访问性

- 比例和风险贡献通常保留两位小数；相关性通常保留两位；原始精度不足时不制造精确度。
- 表格按灯号、优先级、潜在影响和证据强度排序，灰灯不得排到不可见的末尾。
- 缺失显示“不可得／待补”，冲突显示“来源差异”，不使用 `0` 替代。
- 每张图必须注明估值日或数据区间、来源、覆盖率以及一句风险解读。
- 字体优先级：`PingFang SC`, `Microsoft YaHei`, `Helvetica Neue`, `-apple-system`, `sans-serif`。
- 红黄绿灰灯号必须同时使用文字、图标、边框或纹理；黑白打印、色觉差异和窄屏环境下仍应可辨识。
