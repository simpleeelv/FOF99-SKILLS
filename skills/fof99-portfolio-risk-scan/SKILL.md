# 火富牛 FOF 组合风险扫描

> 版本：1.0.3

对基金组合、FOF、母基金或多资产基金配置进行分层风险扫描。先判断数据能支持多深的结论，再识别组合的风险来源、传导路径和处置优先级。将红黄绿灯作为扫描结果的分级工具，不把它当作主动监控服务、收益预测或自动买卖指令。

“火富牛”既用于品牌识别，也代表可选的数据增强能力。检测到已授权的火富牛 MCP 时，可查询基金、净值、指标、相关性、授权组合和私募 FOF 穿透数据；未连接、未授权、无匹配或返回空数据时，仍使用用户持仓、文件、其他数据源和公开披露完成可支持的扫描。

## 数据路由

先遵守用户对来源的明确限制，再选择运行模式：

- **火富牛增强模式**：MCP 可用且用户提供基金名称、代码或已授权组合名称时，自动补充结构化数据。
- **混合核验模式**：用户持仓与 MCP 同时存在时，以用户给出的实际权重、现金、负债和风险预算为准，用 MCP 补充基金属性、净值、指标、相关性和可得穿透信息。
- **通用模式**：MCP 不可用或无数据时，按现有 A／B／C 数据层级继续扫描。

进入增强或混合模式时，必须读取 [火富牛 MCP 路由](references/fof99-mcp-routing.md)。只调用查询工具；不得上传组合、写入数据或执行交易。MCP 数据与用户持仓冲突时并列展示，不静默改变权重或组合事实。

## 核心边界

- 聚焦整个组合的风险筛查、预警和监测，不替代单只基金深度尽调。
- 将回撤底线、流动性匹配和风险集中置于收益讨论之前。
- 区分事实、计算结果、分析判断、情景假设和待核验事项。
- 不把固定阈值当作适用于所有策略、期限和风险预算的绝对标准。
- 不将缺失数据解释为低风险；证据不足时使用灰灯。
- 不编造净值、持仓、规模、申赎条款、管理人或市场事件信息。
- 未获得投资目标、期限、风险承受能力和流动性约束时，不给出个性化调仓指令。

## 工作流程

### 1. 建立组合档案

提取并统一：组合名称、估值日、持仓名称或代码、资产或基金类型、管理人、策略、权重或金额、币种、份额类别、风险预算、业绩基准、投资期限及流动性需求。

- 权重合计不为 100% 时，先查明现金、负债、杠杆、未投金额或数据遗漏；只有在适合时才归一化，并同时保留原始权重。
- 同名基金、不同份额、不同币种或不同净值口径无法唯一匹配时，列出冲突并请求确认。
- 用户仅提供持仓清单时，仍执行结构性风险扫描，不因缺少净值而停止。
- 输出最终报告前，必须读取并使用 [专业报告模板](references/report-template.md)。
- 生成风险仪表盘、正式报告、图表或强调排版的成果时，必须读取 [火富牛风险扫描视觉规范](references/fof99-visual-style.md)；纯文本或 Markdown 输出只应用其中的信息层级、灯号语义和数据格式，不强行模拟网页仪表盘。

### 2. 确定数据层级

按可得证据选择最高可支持层级，并明确哪些结论尚不可得：

| 层级 | 最低数据 | 可完成内容 |
|---|---|---|
| A 结构扫描 | 持仓、权重、估值日 | 单产品、管理人、策略、资产、币种集中度及基础流动性标记 |
| B 量化扫描 | A + 对齐后的净值或收益序列 | 回撤、波动、相关性、高相关簇、风险贡献及净值异常 |
| C 完整扫描 | B + 申赎条款、穿透持仓、杠杆或基准 | 流动性瀑布、底层重复暴露、压力测试、估值滞后和情景损失 |

按用途选择数据来源：

1. 用户提供的 CSV、XLSX、PDF、DOCX、网页、图片或结构化文本用于确定实际组合权重、现金、负债、风险预算和流动性需求。
2. 火富牛 MCP 在可用时补充基金身份、净值、业绩指标、相关性、已授权组合和私募 FOF 穿透数据。
3. 其他已连接且用户有权访问的托管、投研、基金数据库或数据 API 作为补充。
4. 基金管理人、交易所和监管机构披露用于核验正式条款与公开事实。
5. 可追溯第三方信息仅作补充，并标明来源、日期与限制。

必须读取 [风险扫描方法](references/risk-methodology.md)，完成估值日、频率、币种、费率口径、缺失、重复、停更、异常跳变和可比区间检查。关键数据缺失时降低置信度，不得猜测补齐。

### 3. 扫描集中与穿透风险

依次检查单产品、管理人、策略、资产类别、地区、币种和可得底层资产的集中度。至少回答：

- 名义分散是否被同一管理人、同一策略或相同底层暴露抵消？
- 组合是否由少数头寸或高波动头寸主导？
- FOF 是否存在重复持有、关联产品、多层嵌套、未穿透比例或多层费用？
- 现金、负债、衍生品名义敞口和杠杆是否被正确计入？

同时展示最大权重、前 3／前 5 集中度、HHI 或有效持仓数。对于不同策略和风险预算，使用相对基准与用户约束解释指标，不机械套用单一阈值。

### 4. 扫描回撤、相关性与风险贡献

在净值序列通过质量检查后，分析组合及子基金的：

- 最大回撤、峰谷日期、修复时长、最长水下期和当前回撤状态
- 年化波动、下行波动、尾部损失及异常收益点
- 滚动相关性、高相关簇和压力期相关性变化
- 边际或成分风险贡献，以及权重与风险贡献是否明显失衡
- 净值频率、估值滞后或平滑对相关性和波动的低估

相关性只在足够重叠、同频、同币种的收益序列上计算。样本短、低频估值或缺失严重时，将结果标为低置信度；不得把低相关直接解释为稳健分散。

### 5. 扫描流动性与期限错配

将持仓按可变现时间、开放频率、通知期、赎回到账、锁定期、赎回上限、侧袋或暂停条款分层。将组合的资产流动性与用户的现金需求、赎回压力和负债期限对照。

重点识别：

- 表面可赎回但到账慢、需提前通知或受额度限制
- 压力期可能同时降流动性、升相关性和扩大折价的持仓
- 长锁定资产由短期资金支持
- 多层基金结构造成的流动性叠加和信息传递延迟

条款未知时标灰灯，不假设为可随时赎回。

### 6. 执行压力测试

根据组合策略和存续期选择适用方法：

- 历史情景：使用与当前暴露相关且数据覆盖充分的压力区间。
- 假设情景：对权益、利率、信用、商品、汇率、波动率或策略因子设置透明冲击。
- 组合脆弱性：提高相关性、降低流动性、加入估值滞后修正或赎回冲击。
- 反向压力：估算何种冲击会触及用户风险预算或最大可承受回撤。

说明冲击假设、映射方法、未覆盖暴露和模型限制。历史最差表现不是未来损失上限；数据不足时提供情景框架，不伪造数值结果。

### 7. 生成信号灯与行动优先级

必须读取 [信号灯与分级规则](references/signal-framework.md)。每个信号包含：风险对象、指标或事实、阈值或比较基准、当前状态、证据强度、可能影响和建议复核动作。

- **红灯**：已突破风险预算、存在明显期限错配，或在可信证据下可能造成重大组合损失。
- **黄灯**：接近边界、趋势恶化、暴露偏高或需要限期核验。
- **绿灯**：在当前证据与约束下未发现显著异常，不表示无风险。
- **灰灯**：关键数据缺失、过期、冲突或方法不适用，暂时无法判断。

先用用户的风险预算、投资政策或既有阈值；没有时才使用方法文件中的诊断参考区间，并清楚标记为“建议初始阈值，待用户确认”。同一问题不要因多个高度相关指标被重复计数。

## 输出要求

- 使用 [专业报告模板](references/report-template.md)，先给风险总览和前三项优先事项，再给明细。
- 将视觉层级组织为“总体灯号 → 数据覆盖率 → 优先事项 → 风险矩阵与核心图表 → 完整清单 → 复核计划”，并按输出载体应用 [火富牛风险扫描视觉规范](references/fof99-visual-style.md)。
- 报告必须注明估值日、数据区间、数据层级、覆盖率、来源和结论置信度。
- 报告必须注明运行模式、火富牛 MCP 实际覆盖的持仓比例、未命中或无数据的持仓，以及与用户材料的冲突。
- 风险清单按严重性、紧迫性和证据强度排序；区分“立即核验”“限期复核”“持续监测”。
- 有图表能力时，优先生成风险信号矩阵、权重与风险贡献对照、集中度图、相关性热图、回撤图和流动性瀑布图。
- 图表使用白底、一致色板、直接标签和简洁图例；风险仪表盘使用红黄绿灰风险语义，业绩子图才使用红涨绿跌语义，两者不得混用。除颜色外同时使用文字、灯号或图案，确保可访问性。
- 每张图附数据范围、来源和一句核心解读。对缺失或不可比数据显式标记，不做视觉掩盖。
- 结尾给出后续监测指标、触发条件、所需补充数据和研究用途免责声明。

## 失败与安全处理

- 数据源无法访问或文件不可解析时，说明受影响的结论、替代材料和最小所需字段。
- 火富牛 MCP 调用失败时只降低相应持仓或风险维度的覆盖率，不中止扫描；不得要求非火富牛用户必须安装或登录。
- 公开材料与用户数据冲突时，不自行选择有利版本；列出差异并降低置信度。
- 需要当前市场、监管、管理人或基金事件时，核验最新可信来源并注明检索日期。
- 不把预警等级表述为收益承诺、适当性意见或自动买卖建议。
- 只有用户明确要求且提供投资约束时，才在多个可行方案中讨论风险降低路径，并同时说明代价与残余风险。
